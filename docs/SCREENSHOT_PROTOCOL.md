# EAH — Screenshot Protocol

**آخر تحديث:** 2026-11-19
**القاعدة:** Screenshots هي المصدر الوحيد للحقيقة.

---

## المبدأ

لا "أنا أرى"، لا "يعمل"، لا "جربته"، بدون screenshot.
كل ادعاء بصري = screenshot واحد.

---

## متى نطلب screenshots

- بعد كل commit يؤثر على UI
- بعد كل إصلاح (bug أو CSP أو SIGILL)
- قبل بدء ميزة جديدة
- قبل "تم" أو "انتهى"
- عند أي سلوك غريب

---

## كيف نتعامل مع screenshot

1. **نقرأ كل تفصيل** — لا نمر مرور الكرام على أي شيء
2. **نذكر أي خطأ** — حتى لو صغير (حرف مقطوع، لون غريب، محاذاة خاطئة)
3. **نربط بسياق** — "هذا الزر كان يجب أن يكون..."
4. **نصنف**:
   - P1 (حرج): يكسر الوظيفة — إصلاح فوري
   - P2 (متوسط): UX سيء — إصلاح في نفس commit
   - P3 (صغير): بصري — إصلاح في commit منفصل
5. **نسأل عن التفاصيل** — قبل patch، نطلب:
   - Screenshot مكبر للعنصر إذا لزم
   - DevTools Console log
   - Network tab إذا كان fetch

---

## ما يجب أن يحتوي كل screenshot

| العنصر | لماذا |
|---|---|
| **كامل الصفحة** (ليس مقتطف) | نرى السياق |
| **الهيدر ظاهر** | نتحقق من FloatingCapsule |
| **Footer ظاهر** | نتحقق من site-footer |
| **URL في الـ browser** | نتحقق من الصفحة الصحيحة |
| **على 390px** (mobile) | Mobile-first |
| **Console معاً** (اختياري) | أي أخطاء |

---

## القاعدة الذهبية

> **"لا أقول (يعمل) بدون screenshot."**

**حتى لو tsc = 0** — هذا لا يعني UI يعمل.

**حتى لو terminal نظيف** — هذا لا يعني أن المستخدم يرى الصفحة الصحيحة.

---

## خطوات طلب screenshot (للـ AI)

1. **قل بدقة:** "افتح الصفحة X، التقط screenshot كامل، أرسله"
2. **اذكر ما تبحث عنه:** "أحتاج رؤية FloatingCapsule + KPIs + Footer"
3. **اطلب إضافات:** "إذا فيه خطأ أحمر، افتح Console وأرسل log"
4. **لا تقبل "يعمل" كإجابة** — أعد الطلب إذا لزم

---

## خطوات إرسال screenshot (للمستخدم)

1. **Screenshot كامل** (Win: `Win+Shift+S`، Mac: `Cmd+Shift+4`)
2. **لصق** في المحادثة
3. **إضافة:** URL + viewport (mobile/desktop) + أي تفاصيل
4. **إذا فيه خطأ:** Console screenshot معاً

---

## التصنيف الإلزامي

كل screenshot يُراجع، يُصنف:

### P1 — حرج (إصلاح فوري، لا يكمل العمل)
- صفحة لا تفتح
- خطأ أحمر في UI
- زر لا يعمل
- بيانات خاطئة

### P2 — متوسط (إصلاح في نفس commit)
- محاذاة خاطئة
- لون غير مناسب
- نص مقطوع
- overflow

### P3 — صغير (commit منفصل)
- padding صغير
- spacing مختلف
- تحسين بصري

## أمثلة من الجلسات السابقة (للتذكير)

### المثال 1: "P" بدل الصورة
- Screenshot أظهر حرف "P" في avatar
- بدلًا من "يعمل" — فحصنا، اكتشفنا cache
- **الدرس:** "P" لم يكن صورة، كان initial

### المثال 2: Sidebar مكرر 3 مرات
- Screenshot أظهر تكرار
- لم نلاحظه من الكود
- **الدرس:** UI bug لا يظهر من `tsc`

### المثال 3: KPIs = "."
- Screenshot أظهر "." بدل الأرقام
- `toLocaleString('ar-EG')` + خط لا يدعم العربية-الهندية
- **الدرس:** خط VS أرقام

## Checklist بعد كل screenshot

- [ ] فتحت الـ screenshot
- [ ] راجعت كل قسم (Hero, Body, Footer)
- [ ] ذكرت كل خطأ (حتى P3)
- [ ] صنّفت (P1/P2/P3)
- [ ] سألت عن تفاصيل إضافية إذا لزم
- [ ] patch محدد لكل خطأ
