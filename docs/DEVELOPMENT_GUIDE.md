# EAH — Development guide and hand-off

> Last reviewed: 20 November 2026. Verify current branch, workflows and provider state before acting.

## 1. Product contract

EAH is a local Egyptian discovery and activity platform. Its registered roles are exactly:

| User-facing role | Stored key | Scope |
|---|---|---|
| الأدمن | `super_admin` | Platform operations, user moderation and activity management |
| التاجر | `merchant` | Management of the activity linked to the account |
| العميل | `customer` | Discovery, orders and permitted customer interactions |

A visitor is not a role. Role, activity ownership, account standing, verification, subscription, publication and order eligibility must be checked independently. The authoritative rules are in `docs/PRODUCT_SPEC.md` and `docs/ROLES_MATRIX.md`.

Admin-created activities may be ownerless. Selecting an existing user as owner is optional and must not require that user's personal phone. Only published activities belong in public discovery and public activity detail pages.

## 2. Architecture map

The Next.js application is in `web/`.

- `web/app/`: App Router pages, layouts, route handlers and server actions.
- `web/components/`: reusable UI, navigation, cards, forms and client-side widgets.
- `web/lib/auth/`: session, role and authorization helpers.
- `web/lib/data/`: typed read models and server-side data access.
- `web/lib/supabase/`: browser/server/service clients. The service client is `server-only`.
- `web/lib/validations/`: Zod input contracts.
- `web/lib/offline/`: IndexedDB and queued offline mutation support.
- `web/supabase/`: database configuration, SQL tests and local Supabase assets.
- `docs/migrations/`: reviewed SQL changes currently consumed by the isolated RLS workflow.
- `.github/workflows/`: quality, CodeQL, invariants, context-map and isolated DB regression gates.

The current global role-aware navigation is `FloatingCapsule` + `MenuDrawer`. The role layouts provide their workspaces; do not add another sidebar system without checking whether the existing navigation already covers the need.

`docs/CONTEXT_MAP.md` is generated by `npm run context-map`. Read it before introducing a new route, component or service; regenerate it after structural changes.

## 4. Security and data boundaries

- Every server action and API route that mutates or exposes private data must authenticate and authorize on the server; proxy redirects are not authorization.
- `requireAdmin()` verifies a non-anonymous user and the `super_admin` role from `user_roles`.
- Activity ownership is checked separately from role. Never promote or authorize a user just because `owner_profile_id` references them.
- Keep `createServiceClient()` server-only and use it only after a successful authorization check. Audit administrative mutations.
- Public responses must select explicit public fields. Do not include personal phone numbers, private account metadata, owner identifiers or draft status in public payloads.
- Authenticated HTML, Next.js RSC/prefetch payloads and account/admin APIs must not be cached by the service worker. User-specific API responses require `Cache-Control: private, no-store`.
- Validate upload types, sizes and ownership; do not trust client-provided storage URLs or file metadata.
- Keep rate limits fail-closed for security-sensitive write operations.
- SQL functions using `SECURITY DEFINER` need a fixed `search_path`, minimal execute grants and caller/target scoping. Review RLS and function grants together.

## 5. Database and test-data policy

The connected Supabase project named EAH is production. Do not use it for demo accounts, fake activities, destructive tests, test uploads or unreviewed migrations.

The GitHub RLS job requires a separate `SUPABASE_DB_URL` and explicitly rejects the production project ref. That guard must stay enabled. After a dedicated QA database or Supabase branch is approved and configured, use it for:

1. Applying the reviewed migrations in their intended order.
2. Running pgTAP/RLS regression tests under anon, authenticated and service roles.
3. Creating synthetic accounts for the customer (`customer`), merchant (`merchant`) and admin (`super_admin`) roles, plus synthetic activities, only in that isolated environment.
4. Testing optional owner linking, draft/publish visibility, image uploads, search and public activity details.
5. Resetting or discarding the isolated test environment after evidence is recorded.

Never merge an isolated database branch or move test data to production as part of a routine code check.

## 6. UI and accessibility standard

- Mobile-first, RTL and usable at 320–390px. Admin operations must remain practical on a phone.
- Use existing EAH tokens from `web/app/globals.css`; avoid new one-off colors, spacing scales or arbitrary visual systems.
- Keep motion restrained. Honor `prefers-reduced-motion: reduce`; avoid layout-shifting animation.
- Use semantic buttons/links, keyboard navigation, visible focus and accessible names. Dialogs/drawers must trap focus, close with Escape and restore focus.
- Include loading, empty, error and success states. Never show a fake success after an unconfirmed database write.
- Keep touch targets comfortable and prevent horizontal overflow in dashboard grids and forms.

## 7. Quality gates and release discipline

The quality workflow must prove TypeScript, ESLint, Prettier, Stylelint, webpack build, unit tests, production dependency audit, dead-code scan and duplication scan. Keep every gate enabled. The 20 November 2026 baseline reports 170 Prettier violations across the repository; do not describe Prettier as passing while that baseline remains. Track the baseline explicitly, require every changed file to pass formatting, and reduce the legacy backlog in reviewed, one-file-at-a-time changes. Never turn a known baseline into an unreported pass.

For each change, inspect the exact commit's GitHub Actions. A check that failed before a runner starts is an infrastructure failure; a failing test, lint, audit or build after runner assignment is a code/dependency failure.

Vercel deployments, project settings and production aliases are separate from GitHub CI. Do not deploy while the project's documented pause is active. A green CI run is not equivalent to launch approval.

## 8. Required hand-off in every task

At the end of a task, update the relevant docs and report:

- Exact commit SHA and changed paths.
- Behavior/security invariant changed and why.
- Tests run and result, tied to the commit.
- What remains unverified (especially mobile visual QA, RLS/pgTAP, upload flow and production configuration).
- Which database/environment was used.
- Next blockers before launch.

Do not claim a full end-to-end pass unless the test actually covered create → owner linking (including ownerless) → image upload → publish → public search → public detail in an isolated environment.
