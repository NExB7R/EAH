## حسابات الاختبار

يوجد سكربت `qa:seed:accounts` لإنشاء حسابات اختبار، لكنه لا يُشغّل إلا على بيئة غير إنتاجية. يرفض صراحةً project ref الخاص بإنتاج EAH، ويتطلب مطابقة `EAH_QA_ALLOWED_PROJECT_REF` مع ref المشروع المستهدف، بالإضافة إلى `EAH_ALLOW_QA_ACCOUNT_SEED=yes` و`SUPABASE_SERVICE_ROLE_KEY`. لا تُنشئ مستخدمًا بإدخال مباشر في جداول `auth.users`.

من جهاز المطوّر، بعد التأكد من `.env.local` الخاص بمشروع اختبار منفصل، نفّذ:

```bash
cd web
EAH_ALLOW_QA_ACCOUNT_SEED=yes EAH_QA_ALLOWED_PROJECT_REF=<TEST_PROJECT_REF> npm run qa:seed:accounts
```

السكربت ينشئ/يحدّث ثلاثة حسابات محجوزة للاختبار فقط داخل مشروع الاختبار:
- `eah.qa.admin@example.com` — الأدمن (`super_admin` داخل مشروع الاختبار فقط).
- `eah.qa.buyer@example.com` — المشتري (`customer`).
- `eah.qa.seller@example.com` — البايع (`merchant`).

ينشئ كلمات مرور عشوائية قوية ويكتبها محليًا في `web/.qa-test-credentials.local.json` بصلاحية `0600`؛ الملف مستثنى من Git. لا تنسخ كلمات المرور إلى GitHub أو سجلات عامة.

قبل تعديل أي حساب موجود، يتأكد السكربت أن بياناته الوصفية تحمل `eah_qa_account=true`. يرفض لمس أي حساب حقيقي. ينشئ نشاطًا تجريبيًا غير منشور وموسومًا بوضوح إذا لم يكن موجودًا في قاعدة الاختبار، ثم يربط به حساب البايع التجريبي ويجهز إعدادات الطلب. لا ينشئ هذا النشاط في الإنتاج لأن project ref الإنتاجي محظور صراحةً.

### اختبار الأدوار

- **زائر / Anonymous:** التصفح العام فقط. المفضلة والمتابعة والتعليق والإعجاب والتقييم والطلب وكشف بيانات الاتصال يجب أن تعرض قفل تسجيل أو رفضًا من الخادم. RLS تمنع الكتابة حتى لو جرى تجاوز الواجهة.
- **المشتري QA:** جرّب المفضلة والمتابعة والتعليقات والتقييمات والطلب فقط على نشاط QA. لا تختبر التقييمات على نشاط حقيقي.
- **البايع QA:** افتح لوحة البايع، بيانات النشاط، الفروع، إعدادات الطلب، الطلبات، العروض، QR والسمعة. لا تختبر التواصل الفعلي لأن أرقام QA خيالية.
- **الأدمن:** استخدم حساب الأدمن الحالي لمراجعة كل الأنشطة، وإضافة نشاط بلا بايع، وربط مشتري اختباري كمالك اختياريًا، والنشر والصور والبحث. لا تربط حساب الأدمن بالنشاط الحقيقي لأغراض الاختبار.

## ما ثبت وما لم يثبت

- تم نشر آخر تعديل لصفحة العروض على Vercel؛ سجل البناء أكد نجاح Compile وTypeScript وتوليد الصفحات.
- صفحات الإنتاج `/`, `/explore`, `/featured`, `/new`, `/offers` وصفحة تعدد الأرقام رجعت HTTP 200 في فحص HTML، وظهرت صور QA وحالات الطلب.
- صفحة تعدد الأرقام أظهرت `أرقام اتصال (4)` و`أرقام واتساب (4)`.
- عطل تخصيص GitHub Runner التاريخي حُلّ؛ الوظائف تحصل الآن على Runner IDs حقيقية. E2E نجح سابقًا بـ49/49، لكن دورة إنشاء النشاط المصادق عليها ليست ضمن الاختبارات بعد.
- Quality Gate ما زال غير أخضر بسبب ثغرات اعتماديات الإنتاج و119 ملفًا يحتاج Prettier؛ وKnip/jscpd جرى ربطهما لتشغيلهما قبل قرار الفشل النهائي.
- pgTAP/RLS لم يبدأ لأن `SUPABASE_DB_URL` لقاعدة غير إنتاجية غير مضبوط. اختبار business-media-sync أضيف إلى Quality Gate.
- آخر نشر إنتاجي متاح هو commit `bf4377d`. Vercel رفض نشر preview جديد بسبب حد `api-deployments-free-per-day` (انتظار 24 ساعة)، لذلك لا تعتبر تغييرات main اللاحقة منشورة حتى يجري نشر commit محدد والتحقق منه.
- استجابات HTML والبناء لا تثبت النقر والتفاعل الحقيقيين. يلزم تشغيل حسابات QA على قاعدة الاختبار ثم إجراء Playwright للمسارات المصادق عليها.
