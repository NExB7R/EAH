## قواعد الاختبار

- لا تستخدم أي نشاط يبدأ slug الخاص به بـ `eah-qa-test-` كخدمة حقيقية.
- لا ترسل رسائل SMS أو WhatsApp ولا تتصل بالأرقام الظاهرة في خيارات الاختبار؛ الأرقام خيالية ومخصصة لاختبار واجهة الاختيار فقط.
- لا تضف تقييمات/تعليقات/طلبات إلى نشاط حقيقي أثناء QA. اقتصر على سجلات QA المعلّمة.
- لا تغيّر حسابات أو بيانات المستخدمين الحقيقيين. سكربت الحسابات أدناه يرفض تعديل بريد موجود لا يحمل `eah_qa_account=true`.
- لا تنشئ بيئة Supabase مدفوعة أو تغيّر سياسات الإنتاج من أجل الاختبار من دون موافقة صريحة.
- أزل أنشطة وعروض QA قبل **2026-11-05** بعد انتهاء الاختبار، ولا تحذف النشاط الحقيقي `tapooosh`.

## حسابات الاختبار

يوجد سكربت آمن جاهز لكنه **لم يُشغّل بعد** لأن مفتاح Supabase Service Role غير متاح من موصل Vercel (مفتاح حساس غير قابل للقراءة). لا تُنشئ مستخدمًا بإدخال مباشر في جداول `auth.users`.

من جهاز المطوّر، بعد التأكد من `.env.local` الخاص بمشروع `web` ووجود `SUPABASE_SERVICE_ROLE_KEY`، نفّذ يدويًا:

```bash
cd web
EAH_ALLOW_QA_ACCOUNT_SEED=yes npm run qa:seed:accounts
```

السكربت ينشئ/يحدّث بريدين محجوزين للاختبار فقط:
- `eah.qa.buyer@example.com` — المشتري.
- `eah.qa.seller@example.com` — البايع.

ينشئ كلمات مرور عشوائية قوية ويكتبها محليًا في `web/.qa-test-credentials.local.json` بصلاحية `0600`؛ الملف مستثنى من Git. لا تنسخ كلمات المرور إلى GitHub أو سجلات عامة.

قبل تعديل أي حساب موجود، يتأكد السكربت أن بياناته الوصفية تحمل `eah_qa_account=true`. يرفض لمس أي حساب حقيقي. حساب البايع يرتبط **فقط** بالنشاط `eah-qa-test-multi-contact-20261030` ويُفعّل استقبال طلبات EAH لهذا النشاط مع إبقاء `accepts_whatsapp_orders=false`. حساب المشتري يبقى مشتريًا. حساب الأدمن الحالي هو حساب المنصة الإداري؛ لا ننشئ أدمن وهميًا أو نمنح `super_admin` إضافيًا.

### اختبار الأدوار

- **زائر / Anonymous:** التصفح العام فقط. المفضلة والمتابعة والتعليق والإعجاب والتقييم والطلب وكشف بيانات الاتصال يجب أن تعرض قفل تسجيل أو رفضًا من الخادم. RLS تمنع الكتابة حتى لو جرى تجاوز الواجهة.
- **المشتري QA:** جرّب المفضلة والمتابعة والتعليقات والتقييمات والطلب فقط على نشاط QA. لا تختبر التقييمات على نشاط حقيقي.
- **البايع QA:** افتح لوحة البايع، بيانات النشاط، الفروع، إعدادات الطلب، الطلبات، العروض، QR والسمعة. لا تختبر التواصل الفعلي لأن أرقام QA خيالية.
- **الأدمن:** استخدم حساب الأدمن الحالي لمراجعة كل الأنشطة، وإضافة نشاط بلا بايع، وربط مشتري اختباري كمالك اختياريًا، والنشر والصور والبحث. لا تربط حساب الأدمن بالنشاط الحقيقي لأغراض الاختبار.

## ما ثبت وما لم يثبت

- تم نشر آخر تعديل لصفحة العروض على Vercel؛ سجل البناء أكد نجاح Compile وTypeScript وتوليد الصفحات.
- صفحات الإنتاج `/`, `/explore`, `/featured`, `/new`, `/offers` وصفحة تعدد الأرقام رجعت HTTP 200 في فحص HTML، وظهرت صور QA وحالات الطلب.
- صفحة تعدد الأرقام أظهرت `أرقام اتصال (4)` و`أرقام واتساب (4)`.
- GitHub Actions ما زالت تتوقف قبل أي خطوة بـ `runner_id=0` و`steps=[]`. لذلك لم تُشغّل Vitest أو Playwright أو pgTAP من Actions.
- استجابات HTML والبناء لا تثبت النقر والتفاعل الحقيقيين. يلزم تشغيل حسابات QA ثم إجراء اختبار يدوي/Playwright بعد حل Runner.
