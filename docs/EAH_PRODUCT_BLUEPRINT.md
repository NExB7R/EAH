# EAH Product & Experience Blueprint

> **الحالة: اتجاه مبدئي متفق عليه — 2026-10-29.** هذه الوثيقة تحفظ متطلبات التصميم، ولا تعني أن تنفيذها أو اختبارها اكتمل.
> مرجع الهوية الحالي هو لقطة الشاشة التي قدمها صاحب المشروع في 2026-10-29. عند التعارض تكون الأولوية للعناصر الثابتة أدناه.

## 1. الهدف
تطوير EAH كمنصة اكتشاف أنشطة محلية مصرية جذابة وسريعة وموثوقة، تبدأ بالموبايل، مع تنقل واضح وخلفية تخدم الأنشطة وبحث وتصنيفات وترتيب مفهوم. نطوّر الموجود بدل إعادة تصميم عشوائية أو هدم الهوية.

## 2. عناصر الهوية الثابتة
لا تُحذف أو تُستبدل أو يعاد تأليفها دون موافقة صريحة:
- الخلفية الداكنة وهوية البنفسجي/النيون والتوهج واللمسات الذهبية.
- لوجو EAH الحالي والتاج الذهبي وشكلهما ونسبهما.
- عبارة اللوجو: **«اللي نفسك فيه؟»**.
- الهوك بالنص والترتيب والحركة المقصودة: **«شبيك لبيك كل حاجة حواليك»**.
- عبارة شبين القناطر: **«دولة شبين القناطر تتحدث»**.
- **«فلسطين في القلب»** والعلم، والإمضاء الذهبية الحالية.
- عناصر الفوتر الأساسية وحقوق النشر والإصدار وروابط المساعدة والأدوار.
يجوز تحسين المقاس والموضع والتوزيع والاستجابة، مع الحفاظ على النصوص والمعنى والحركة المقصودة. لا تُخترع بيانات تواصل أو روابط رسمية.

## 3. اتجاه التصميم
دمج انتقائي، وليس قالبًا واحدًا لكل الصفحات:
1. Neon Discovery: الهوية الحالية وإضاءة محسوبة.
2. Modern Marketplace: عرض واضح وعملي للأنشطة.
3. Trust First: معلومات ثقة لا تظهر إلا ببيانات فعلية.
4. Dashboard Pro: لوحات عملية حسب الدور.
5. Adaptive EAH: نظام موحّد مع تخطيط يناسب وظيفة كل صفحة.
لا تغيّر الألوان إلى درجات باهتة لمجرد التجديد. صور الأنشطة ومحتواها هي محور الاهتمام.

## 4. الخلفية والأداء
- خلفية داكنة عميقة مع تدرجات وهالات بنفسجية/ذهبية ناعمة ونقوش دقيقة عند الحاجة.
- الخلفية تبرز الصور ولا تنافسها.
- فضّل CSS gradients والطبقات الخفيفة بدل فيديو الخلفية أو Canvas الثقيل.
- تجنّب تحريك طبقات كبيرة باستمرار أو blur/filter مكلف على مساحات ضخمة.
- التزم بـ `prefers-reduced-motion` ولا تجعل الحركة ضرورية لفهم المحتوى.
- امنع القفزات في التخطيط، وراعِ Core Web Vitals وسرعة أجهزة أندرويد المتوسطة.

## 5. التنقل
- انتقال واضح ومتسق بين الرئيسية والاستكشاف والتفاصيل والمساعدة.
- الهيدر/القائمة العائمة والقائمة الجانبية وشريط الموبايل والفوتر لا تتنافس أو تكرر الروابط بلا سبب.
- تسميات مفهومة وحالة نشطة واضحة وأهداف لمس مناسبة، مع إغلاق موثوق للقوائم بعد التنقل.
- دعم RTL وsafe-area ولوحة المفاتيح وقارئ الشاشة.
- انتقالات قصيرة غير معطلة؛ مراجعة الروابط المكسورة والمكررة والقوائم حسب الدور.

## 6. البحث والتصنيفات والترتيب
### البحث
- حقل واضح في الهيرو والاستكشاف، إرسال بـ Enter، وزر بحث واضح؛ الصوت متاح فقط مع دعم المتصفح وبديل مناسب.
- الاحتفاظ بمعايير البحث عند الانتقال والعودة، وحالات مفهومة للتحميل والنتائج الفارغة والأخطاء.
- لا تظهر أنشطة غير منشورة للمشتري.
- الفلاتر المتقدمة واضحة، تعرض المختار، ويسهل مسحها.

### التصنيفات
- تعتمد على أنواع الأنشطة الفعلية وإعدادات الأدمن، لا قائمة ثابتة تتعارض مع البيانات.
- على الهاتف: صف قابل للتمرير أو شبكة مرنة وفق الاختبار، دون قص أو التفاف عشوائي.
- «استكشف الكل» ظاهر، والتصنيف النشط واضح ويمكن إلغاؤه.
- توافق التصنيفات مع البحث والروابط العميقة وقوائم الاستكشاف.

### الترتيب
- فصل ترتيب المستخدم عن الترند/التوصية.
- خيارات مفهومة مثل الأحدث، الأقرب عند توفر موقع صالح، الأعلى تقييمًا عند وجود بيانات كافية، والمميز عند وجود تمييز معتمد.
- لا تُظهر «الأفضل» دون بيانات كافية؛ لا تستخدم التقييم أو الموقع للتضليل.
- وضّح الإعلانات/التمييز المدفوع إذا ظهر في النتائج.

## 7. كارت النشاط وصفحة التفاصيل
- صورة رئيسية واضحة مع fallback ومقاس ثابت لتجنب قفزات التخطيط.
- الكارت يعرض الاسم والنوع والموقع وملخصًا مختصرًا وحالة الفتح عند توفر ساعات صحيحة، ومؤشرات التقييم/التوثيق فقط عند استحقاقها.
- لا يكدّس الكارت كل المعلومات؛ التفاصيل والتواصل والفروع والساعات والعروض في صفحة النشاط.
- صفحة التفاصيل ترتب الصورة والهوية والاسم والتصنيف والموقع والحالة والملخص وساعات العمل ووسائل التواصل والفروع/الخدمات ثم التقييمات والعناصر الإضافية المتاحة.
- الصور متطابقة بين الكارت والتفاصيل، مع fallback سليم.
- لا تعرض شارات ثقة أو تقييمات أو حالة «مفتوح» دون بيانات صحيحة.

## 8. الأدوار وقواعد النشاط
الأدوار الظاهرة ثلاثة فقط:
- **الأدمن:** إدارة المنصة والأنشطة والمستخدمين والإعدادات والصلاحيات.
- **البايع:** إدارة النشاط المرتبط به فقط.
- **المشتري:** اكتشاف الأنشطة وإدارة حسابه وتفضيلاته.
قواعد النشاط: الأدمن يستطيع إنشاء نشاط بلا مالك، ويمكنه اختياريًا ربط مستخدم واحد موجود كمالك؛ ظهور النشاط العام يتبع حالة النشر لا وجود المالك. لا تُمنح الملكية برقم هاتف أو نموذج عام، ولا يرث المالك الجديد إعدادات طلبات مفعّلة من مالك سابق دون تحقق صريح.

## 9. الموبايل والاستجابة
- اختبر عروض 320، 360، 375، 390، 430px، ثم التابلت والكمبيوتر.
- امنع التمرير الأفقي غير المقصود وتداخل الهيدر وقص الهوك/اللوجو وتصادم الأزرار.
- راعِ safe-area وأهداف لمس عملية وخطوطًا مقروءة وRTL.
- حمّل الصور بالمقاسات والاستراتيجية المناسبة، وراعِ التركيز والتباين والتسميات المساعدة وتقليل الحركة.

## 10. قواعد التنفيذ
- العمل على `main` فقط حسب تفضيل صاحب المشروع؛ لا تنشئ فروع معاينة جديدة.
- راجع المكونات وCSS والبيانات قبل التعديل، وغيّر أصغر نطاق متماسك.
- لا تغيّر الهوية الأساسية أو النصوص ولا تخترع بيانات تواصل.
- تجنب إضافة مكتبات أو صور أو مؤثرات ثقيلة إذا أمكن تحقيق المطلوب بالأدوات الموجودة.
- لا تُجرِ تغييرات إنتاجية في قاعدة البيانات لأجل تحسين بصري.
- وثّق القرارات والاختبارات في `docs/PROGRESS.md` والوثائق ذات الصلة.
- البناء وحده ليس دليلًا على اكتمال الرحلة.

## 11. خطة التنفيذ واختبارات القبول
1. تسجيل الكروكي ومراجع الهوية التي يقدمها صاحب المشروع وتحويلها لمواصفات شاشة متفق عليها.
2. مراجعة الهيدر والقائمة والهيرو والبحث والتصنيفات والخلفية والكروت والتفاصيل والفوتر.
3. إصلاح التنقل والتكرار وحالات القوائم والاستجابة دون كسر الوظائف.
4. تحسين الخلفية والحركة والأداء وفق المعايير أعلاه.
5. ضبط البحث والتصنيفات والفلاتر والترتيب على البيانات الحقيقية.
6. تحسين الكارت والتفاصيل ومراجعة رحلات الأدمن والبايع والمشتري.
7. تشغيل lint/typecheck/build والاختبارات المتاحة وإصلاح الإخفاقات.
8. التحقق من النشر وصفحات الموبايل وسجلات التشغيل، ثم اختبار إضافة نشاط كاملة في بيئة آمنة.
لا يُعلن الإطلاق جاهزًا حتى تُختبر رحلة إنشاء النشاط والصور والمالك الاختياري والنشر والبحث والتفاصيل والصلاحيات.

## 12. قرارات مفتوحة
- تفاصيل الكروكي النهائي لكل شاشة.
- الملفات الأصلية الدقيقة للتاج/السلوجان/الهوك/حملة شبين القناطر وفلسطين/الإمضاء إذا اختلفت عن لقطة الشاشة.
- ترتيب الأولويات النهائي لأقسام الرئيسية وفق الكروكي والبيانات الفعلية.
- حسابات غير إنتاجية لاختبار رحلات المشتري والبايع.
لا يُخترع بديل لهذه النقاط قبل حسمها.
