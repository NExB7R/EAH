# EAH — الدستور والقواعد الحاكمة (The Constitution)

> **تحذير:** هذا الملف هو المرجع الأعلى لكل قرار في المشروع. أي AI أو مطور جديد يجب أن يقرأه أولا.

## 1. قواعد المالك (Owner's Directives)
- **واحدة واحدة**: خطوة بخطوة، بدون أخطاء، مع مراجعة كل حاجة قبل ما تتقفل.
- **صفر تجاهل**: أي حاجة غلط أو غير منطقية أو ملهاش لازمة تتشال أو تتصلح فورًا.
- **قلة الكلام، كثرة التنفيذ**: مفيش كلام كتير، تنفيذ ومراجعة.
- **Mobile-First إجباري**: أي قرار تصميم يبدأ من الموبايل (320px).
- **2026/2027**: أحدث وأسرع وأذكى الحلول التقنية.
- **Main فقط**: شغل على `main`، مفيش فروع كتير.
- **قابلية التطوير**: الكود والتوثيق يكونوا واضحين لأي مطور أو AI.
- **القيمة**: منصة لا تقدر بثمن من ناحية التجربة، السرعة، الأمان، والتصميم.
- **التوثيق**: كل خطأ أو تجربة أو قرار يتسجل عشان منكررش الأخطاء.

## 2. قواعد الأمان والخصوصية
- 2FA إجباري على: GitHub, Vercel, Supabase, Cloudinary.
- ممنوع أي Secret في الكود. فقط `.env.local` (gitignored) أو منصات الـ Secrets.
- أي توكن اتكشف في التاريخ = يعتبر محروق ولازم يتغير (Rotate).
- الريبو يفضل Private في الإنتاج. الـ Public مسموح مؤقتًا فقط لتوفير موارد الـ CI بشرط تنضيف التاريخ.

## 3. قواعد الموارد (Resource Budget)
- **Vercel**: Free tier (100GB bandwidth, 6000 build mins). ممنوع builds فاشلة متكررة.
- **GitHub Actions**: Free tier (2000 mins/شهر). ممنوع push عشوائي على فروع. E2E على main فقط.
- **Supabase**: Free tier (500MB DB). ممنوع queries غير indexed.
- **القاعدة الذهبية**: نستغل المجاني 100% قبل أي دفع. الترتيب: Vercel -> Supabase -> Cloudinary -> GitHub.

## 4. قواعد التعامل مع الـ AI
- اقرأ `AGENTS.md` و `docs/CONSTITUTION.md` أولا. اشتغل على `main` فقط.
- استخدم TypeScript strict، Server Components، Zod للتحقق.
- حافظ على الهوية البصرية (Dark-only, Neon, RTL) والتصميم Mobile-First.
- أي تغيير في قاعدة البيانات يحتاج Migration جديدة + موافقة صريحة.
- سجل كل تغيير في `docs/PROGRESS.md` و `docs/ERROR_REGISTER.md`.
