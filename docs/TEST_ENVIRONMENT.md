# EAH — بيئة الاختبار المعزولة (QA)

> **الحالة الحالية — 2026-11-21:** فحص قائمة مشاريع Supabase المتصلة أعاد مشروعًا واحدًا فقط باسم EAH، وهو مشروع الإنتاج المعروف؛ لم تظهر أي قاعدة أو مشروع QA مستقل. لذلك جميع اختبارات قاعدة البيانات وعمليات إنشاء الحسابات والأنشطة والرفع والتنظيف **متوقفة**. الفحص كان قراءة metadata فقط ولم يتصل بقاعدة البيانات أو يكتب فيها.

## حدود السلامة

- لا تستخدم مشروع Supabase الإنتاجي لأي seed أو اختبار كتابة أو migration أو رفع ملفات أو تنظيف.
- لا تفترض أن الأنشطة أو الحسابات التي سُمّيت «تجريبية» موجودة في QA؛ وجود علامة أو اسم تجريبي لا يثبت أن قاعدة البيانات معزولة.
- لم يتم في هذه الجلسة إنشاء أو تعديل أو حذف أي حساب أو نشاط أو طلب أو صورة أو سجل في Supabase.
- لا تشغّل web/scripts/seed-qa-accounts.mjs حاليًا. السكريبت يستخدم Service Role ويكتب في Auth وprofiles وuser_roles وbusinesses وmerchant_order_settings.
- يجب أن تكون قيمة المشروع المسموح بها هي Project Ref لقاعدة QA مستقلة فقط، مع التحقق يدويًا من عنوان Supabase قبل التشغيل. وجود متغير السماح وحده ليس إثباتًا أن المشروع غير إنتاجي.
- لا تشغّل docs/seeds/cleanup.sql؛ لا توجد قائمة fixtures معتمدة أو مطابقة بيانات حديثة تثبت أن السجلات المستهدفة آمنة للحذف.

## بيانات اعتماد وfixtures تاريخية

- حُذفت من هذه الوثيقة بيانات الدخول الثابتة ومعرّفات الحسابات التي كانت موثقة سابقًا؛ لا تنسخها من سجل Git أو من نسخ قديمة ولا تستخدمها.
- اعتبر أي كلمة مرور اختبار ثابتة نُشرت سابقًا في المستودع مكشوفة. يلزم تدويرها أو تعطيل الحسابات المرتبطة بها بعد تحديد الحسابات الفعلية ومراجعتها من مالك المشروع، دون تعديل بيانات الإنتاج من جلسة العمل هذه.
- لا يوجد في هذه الوثيقة اعتماد على أن الحسابات أو الأنشطة أو التفاعلات التاريخية ما زالت موجودة أو صالحة.
- لا تحفظ كلمات مرور أو Service Role keys أو Access Tokens أو UUIDs لحسابات أشخاص داخل المستودع أو سجلات التوثيق. تُدار أسرار QA في مدير أسرار بيئة QA فقط، وتُكتب بيانات الدخول المؤقتة محليًا في ملف مستثنى من Git بصلاحيات مقيدة.

## شروط اعتماد QA قبل أول اختبار

1. اعتماد إنشاء مشروع Supabase منفصل تمامًا عن الإنتاج — لا يوجد حاليًا سوى مشروع EAH الإنتاجي — ثم التحقق من Project Ref وURL من لوحة Supabase.
2. إعداد أسرار منفصلة لقاعدة QA، وعدم إعادة استخدام Service Role Key أو مفاتيح الإنتاج.
3. التأكد من أن حارس السكريبت يرفض Project Ref الإنتاج حتى عند ضبط متغيرات التفعيل والسماح.
4. مراجعة migrations وRLS والـtriggers على QA فقط، مع snapshot/نسخة قابلة للاسترجاع.
5. إنشاء fixtures بأسماء وعلامات واضحة، وعدم استخدام حسابات أشخاص حقيقيين أو أرقام هواتفهم.
6. تسجيل SHA للنسخة المختبرة، ونتائج الاختبارات، ومراجع fixtures غير الحساسة فقط.

## سيناريوهات التحقق المطلوبة — غير منفذة حاليًا

### زائر
- [ ] فتح الصفحة الرئيسية والاستكشاف والتفاصيل العامة.
- [ ] التأكد أن المسودات والأنشطة غير المنشورة لا تظهر في البحث أو الصفحة العامة.
- [ ] التأكد أن أرقام الهاتف وواتساب الخاصة لا تظهر في HTML أو RSC payload أو بيانات الصفحة.

### العميل (customer)
- [ ] تسجيل الدخول بحساب QA معزول.
- [ ] اختبار المفضلة والمتابعة والتقييم والتعليق وكشف التواصل وفق الصلاحيات.
- [ ] التأكد من رفض التفاعلات للحساب المقيد مع بقاء الصلاحيات المسموحة فقط.

### التاجر (merchant)
- [ ] التأكد من رؤية نشاطه المرتبط فقط.
- [ ] مراجعة إحصائيات اليوم بتوقيت Africa/Cairo.
- [ ] اختبار الطلبات داخل المنصة بصورة منفصلة عن طلبات واتساب.
- [ ] اختبار حالات الاتصال وانقطاع الشبكة والطابور دون تكرار العمليات.

### الأدمن (super_admin)
- [ ] إنشاء نشاط بلا مالك.
- [ ] إنشاء نشاط مع ربط مستخدم موجود اختياريًا، دون طلب رقم هاتفه الشخصي.
- [ ] رفع الشعار والغلاف، والتحقق من تنظيف الملفات عند فشل الحفظ.
- [ ] التأكد أن النشاط يبدأ كمسودة ولا يظهر للعامة قبل النشر الصريح.
- [ ] النشر ثم التحقق من ظهوره في البحث وفتح الصفحة العامة.
- [ ] التأكد من أن صلاحيات الإدارة محمية من حساب العميل والتاجر.

## تقرير الاختبار

لا توجد نتائج نجاح حديثة مثبتة لهذه السيناريوهات. لا تُحوّل أي خانة إلى مكتملة إلا بعد تشغيل الاختبار على QA المعزولة وتسجيل SHA ونتيجة واضحة. Build أو TypeScript وحدهما لا يثبتان نجاح مسارات قاعدة البيانات أو E2E.

## التنظيف بعد QA

أي تنظيف مستقبلي يتطلب:
- قائمة دقيقة بالـfixtures التي أنشأها الاختبار على QA فقط.
- مراجعة علاقات السجلات التابعة وخطة rollback.
- تحققًا نهائيًا من Project Ref قبل التنفيذ.
- عدم تنفيذ حذف جماعي على الإنتاج، وعدم افتراض أن prefix مثل demo- وحده يثبت ملكية السجل للاختبارات.
